# 追问问题（15 个）

> 用途：补齐业务口径与数据边界，避免 Demo 做偏；也用于 kickoff 中快速收敛范围。

1. 目标国家/站点是哪个（单站点还是多站点）？如果多站点，是否需要币种统一（FX）？

2. 选品决策更关心“销量体量”还是“增长/趋势”（爆发）？两者的优先级如何？

3. “Top selling”的业务定义是什么：按销量、GMV、订单数、热度还是榜单 rank？是否允许混合 proxy？

4. 在合规前提下（ToS/robots/数据权限），TikTok Shop 与 Shopee 各自能稳定拿到哪些字段？（sold、reviews、likes、直播相关等）如果拿不到 sold，最接受的替代 proxy 是什么？

5. Top N 的期望值是多少（100/200/500/1000）？对比与展示希望覆盖到多深的长尾？

6. 时间窗在 7/14/30 天中更偏好哪个？希望能否做成可切换参数？

7. 类目层级如何定义：用平台类目、还是需要映射到你们内部类目树？是否有现成类目映射表？

8. 对“同款”的严格程度：

- 必须同品牌+同规格吗？
- 同系列不同规格是否也算“覆盖”？

9. 你们更希望 matching 输出到哪个粒度：

- 商品级（item）
- 变体级（variant/sku）
- 还是“系列/家族”（family）？

10. 人审角色是谁（品类经理/运营/分析）？可接受的审核量级是多少（每天 20/50/200）？是否需要保留审核/override 的审计与回放（规则版本、reasons 结构化）？

11. 我方 SKU 数据可用到什么程度：

- 是否提供核心 SKU 子集（500–2000）？
- 是否有品牌/规格/条码等字段支持更严格对齐？

12. “harvestable（可采）”如何定义：

- 有既定供应商库/可采清单吗？
- 还是 Demo 允许用简单规则/人工标注 stub？

13. 预警希望覆盖哪些业务场景优先：

- 爆款突增
- 价格异常
- 平台差异
- 竞品促销
  严重度（severity）如何定义？

14. 价格带（price band）希望按什么方式分桶：固定区间、分位数、还是你们内部价格段定义？

15. Demo 评审时最希望看到的“1–2 个关键故事”是什么？例如：

- “TikTok 某品牌突然爆发，我们未覆盖且可采 → 机会清单”
- “两平台同类价格带差异明显 → 定价调整建议”
