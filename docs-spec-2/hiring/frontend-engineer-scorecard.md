# Frontend Engineer — 面试评分表

## 使用方式

- 适用于 Frontend Engineer 岗位的 Round 1 / Round 2
- 每项按 1-5 分评分：1 = 明显不达标，2 = 偏弱，3 = 基本达标，4 = 明显胜任，5 = 超预期
- 建议总分门槛：$\ge 3.5 / 5$
- 以下项目中，`数据可视化设计`、`性能优化能力` 不应低于 3 分

## 评分维度

| 维度             | 权重 | 核心判断                                              |
| ---------------- | :--: | ----------------------------------------------------- |
| 数据可视化设计   | 25%  | 是否能把业务问题转成合理图表和页面布局                |
| 性能优化能力     | 20%  | 是否能处理大表格、大列表、复杂状态场景                |
| 异步与状态管理   | 20%  | 是否能设计可靠的 loading / error / empty / stale 体验 |
| 代码质量与重构   | 20%  | 是否具备组件拆分、抽象和 review 能力                  |
| 沟通与 ownership | 15%  | 是否清晰、主动、适合小团队协作                        |

## 重点题目与观察点

### 题目 1：Dashboard 设计题

**题目：** 给 200 SKU × 2 平台 × 30 天价格数据，设计一个页面让业务快速发现异常、趋势和跨平台差异。

**重点观察：**

- 是否会按问题选图，而不是机械堆图
- 是否知道趋势、排名、异常、对比要分层展示
- 是否能解释页面信息层级

**高分信号：**

- 会先定义用户任务，再选图
- 能说出首屏卡片、图表区、筛选区、明细区之间的关系
- 能识别异常优先级和 drill-down 路径

**低分信号：**

- 只会说折线图、柱状图，但解释不出为什么
- 页面结构混乱，没有用户路径
- 不考虑筛选、排序、异常高亮

### 题目 2：5000 行表格性能题

**题目：** React 列表 5000 行 × 10 列，可排序、筛选、分页，如何做？

**重点观察：**

- 是否知道虚拟列表、memo、分页、服务端筛选
- 是否能区分渲染问题和数据问题
- 是否能权衡易用性和性能

**高分信号：**

- 主动提到 virtualization、状态边界、服务端分页/筛选
- 能谈 profiling、重渲染来源、列渲染优化
- 会根据数据量和交互要求给不同方案

**低分信号：**

- 只说“做分页”
- 不理解为什么会卡
- 无法定位性能瓶颈来源

### 题目 3：多接口部分失败题

**题目：** 页面同时请求 3 个 API，其中 1 个失败，界面如何处理？

**重点观察：**

- 是否理解局部失败与整体失败的区别
- 是否知道 query 缓存、重试、回退和状态提示设计
- 是否从用户视角考虑页面反馈

**高分信号：**

- 能设计局部 error state 和部分内容可用的 UI
- 会谈缓存、重试条件、stale 数据展示
- 能避免“一处失败整页白屏”

**低分信号：**

- 只会 toast 报错
- 不区分 blocking / non-blocking 错误
- 没有降级思路

### 题目 4：代码 Review / 重构题

**题目：** 对现有业务组件做 review，并给出重构建议。

**重点观察：**

- 是否能发现结构问题，而不仅是格式问题
- 是否知道组件拆分、hook 抽象、状态边界
- 是否考虑测试和未来扩展性

**高分信号：**

- 能指出命名、职责、状态耦合、复用性问题
- 重构建议明确且不过度设计
- 能解释为什么这样改更易维护

**低分信号：**

- 只关注样式和代码格式
- 拆分建议过度或无逻辑
- 无法说明 trade-off

## Red Flags

- 只做过营销页/官网，几乎没有数据产品经验
- 无法解释自己项目中的关键取舍
- 缺乏基本性能优化认知
- 交流中持续模糊、空泛、回避细节
- 对模糊需求明显抗拒
