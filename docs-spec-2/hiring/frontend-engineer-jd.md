# Frontend Engineer — Pricing Center

## 职位概述

我们正在建设一个面向东南亚电商的 Pricing Center，帮助客户跟踪 Shopee、TikTok Shop、Lazada 等平台的价格变化、商品匹配结果和异常机会。

该岗位负责把现有 MVP 前端产品化，交付客户可用的 Dashboard、审核工作台和分析页面。

## 你将负责

- 将现有 React MVP 产品化，交付可演示、可试用、可迭代的 Dashboard
- 实现价格趋势、排名变化、跨平台对比、告警明细等核心页面
- 对接后端 API、认证流程、审核工作台与数据可视化组件
- 优化性能、可维护性、可测试性和页面交互体验
- 与产品和技术负责人一起快速迭代真实客户场景

## 任职要求

### Must Have

- 3-5 年 React + TypeScript 开发经验
- 做过数据密集型 B2B Dashboard、运营平台或分析系统
- 熟悉表格、图表、筛选、分页、复杂状态管理等前端场景
- 理解性能优化，包括大列表渲染、缓存、代码拆分、请求并发处理
- 能独立拆解需求并推进落地，而不是只做切图和页面拼装

### Nice to Have

- 有 OIDC / OAuth2 / Cognito / Auth0 接入经验
- 有电商、定价、BI、SaaS 产品经验
- 有 Figma 到前端落地经验
- 用过 Recharts、ECharts、TanStack Query、Zustand

## 我们更看重什么

- 能不能把抽象业务问题拆成合理页面结构和交互流
- 能不能做出数据产品，而不是普通展示页

## 面试会重点考察的具体内容

### 1. 数据可视化设计能力

候选人需要能够回答：

- 价格趋势适合用什么图
- 排名变化适合用什么图
- 跨平台对比如何布局才让人一眼看懂
- 异常告警如何排序与高亮

**我们想看到的信号：**

- 会按任务目标选图，而不是只会堆图表
- 能说出“用户先看什么、再看什么、为什么”
- 会平衡信息密度与可读性

### 2. 前端性能能力

候选人需要能够回答：

- 5000 行表格如何渲染和交互
- 排序、筛选、分页、虚拟列表如何取舍
- 首屏慢、接口慢、组件重渲染多时怎么排查

**我们想看到的信号：**

- 知道虚拟列表、memo、缓存、拆包、懒加载
- 能区分“CPU 问题、网络问题、状态问题、渲染问题”
- 不会只说“加 loading”

### 3. 异步状态与容错设计

候选人需要能够回答：

- 多接口并发请求时如何处理部分失败
- Query 缓存和重试策略如何设置
- 用户看到的 loading / empty / error / stale 状态该如何设计

**我们想看到的信号：**

- 会从用户体验和工程实现两边思考
- 知道 query key、缓存失效、重试边界
- 不会把所有错误都简单弹 toast

### 4. 代码质量与重构能力

候选人需要能够完成：

- 对现有组件做 code review
- 指出命名、状态边界、组件拆分、复用性、可测试性问题
- 给出合理重构方案

**我们想看到的信号：**

- 不是只挑格式问题
- 能指出结构性问题并给出更清晰的组件边界
- 理解什么时候抽 hook、什么时候拆组件、什么时候保持简单
